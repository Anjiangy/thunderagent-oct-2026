两臂差 **1.5%（pin 反而略差）**，与上次的“pin 低 13.2%”相反。

## 为什么：pin 根本没生效

`curl :8102/v1/programs` 显示 **49 个 program 全部 pinned 到 'a'（它唯一的后端）**，但这只影响 executor 自己的放置决策；而请求是 **TA 直接指定后端** 转发进来的，executor 只做转发，pin 不参与路由。

⇒ 上次那 13.2% 是 TA 首轮路由的偶然（那一跑恰好把 12 个都分到了 B，与预热位置重合）；这次 TA 正常均分，两臂就一样了。

## 结论（改写 E5）

1. **per-card 拓扑下，“把路由指对”不是免费可选项**——它要求改 TA 的放置逻辑（program→卡 亲和），executor 做不到。
2. 所以 E5 的真实选择只有两个：**放任错配**（有 KV 的卡不用，重算）或 **真搬**（付 0.61× 重算把 KV 搬过去）。
3. 按已测数字算：真搬代价 ≈0.41 s/次，能拿回的收益 ≈0.28 s/次（中位） → **净 −0.13 s，不划算**。
4. 因此“迁移”在这个场景里**没有独立价值**；要让 KV 位置发生作用，唯一经济的方式是**把 program 亲和记账上移到 TA 的调度器里**（免费），而不是加一个搬运层。

这条结论对论文/方案的口径影响很大：写在“迁移方案”名下是不成立的，应写成“**KV 位置应当成为路由器的输入**”。
