## 边际收益

| 区间 | 每多搬一个省下 |
|---|---|
| 第 1~2 个 | **79k** |
| 第 3~4 个 | **127k**（最大） |
| 第 5 个以后 | **≈0**（−2k / +2k 是噪声） |

**在第 4 次归零。** 之后再搬就是纯粹的浪费：被搬的 program 要在新卡重付一次 prefill，而热卡早已不超容。

## 为什么会饱和在第 4 个：一个可以直接写进策略的算式

- 需求 `D = 16 × 9k = 144k`，单卡容量 `K = 121k`；
- 每个 program 平均 `p = 9k`；
- **需要搬走的最小数 = ⌈(D − K) / p⌉ = ⌈23/9⌉ = 3**。

实测饱和在 **4**，与算式吻合（第 3 个刚好把热卡压到容量线以下，第 4 个提供保险；2 个不够，仍差 5k）。
⇒ **搬迁数量应该按需求算，而不是"能搬就搬"**：`moves = ceil((D_hot − K) / p̄)`，再多搬只会增加成本。

这也解释了为什么第 3~4 个的边际收益最高：它们正好是"跨过容量线"的那一步，前面两个只是在减需求、还没过线；过了线之后，剩下的 program 全部不再互相驱逐，收益一次性结算。

## 成本对照

搬 4 个的成本 ≈ 4 × 9k = **36k** 的 prefill；省下 **413k** 重算 → **约 11 倍**。
且成本是一次性的，收益在后续每一轮都复利（第 2 轮起每轮只重算 558 token）。

## 结论

1. **该搬，而且要搬"刚好够"**：`⌈(D−K)/p⌉` 个。
2. 搬多没有惩罚性变差（4/6/8 在噪声内），但**没有收益**，且每个都付一次 prefill。
3. 因此平衡器的最优策略是"算差额"，不是"循环搬直到不满足条件"——当前实现在差额覆盖后仍会继续扫描，属于可以省掉的空转。
