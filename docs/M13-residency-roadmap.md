# 主动 KV 驻留：工程与实验路线（v2）

> v1 → v2 的三处结构性修改（源于 2026-10-27 的三条补充）：
> 1. **主指标改成吞吐**（step/min 一类），重算量降级为诊断指标；
> 2. **环境改成"一卡一 Docker、多 SSH"**，每个实验开头必须声明"要几张卡、是否同机"；
> 3. **新增交付形态**：模仿 `request-throttling-controller` 出一个 **Residency Controller Mod**，并证明其效果。

## 1. 目标重定义：吞吐优先

### 1.1 主指标

| 指标 | 定义 | 用途 |
|---|---|---|
| `step/min`（端到端） | 真实 agent：完成步数 ÷ 墙钟（分） | **最终判据**，仅在真实 agent 实验（E6/E9）里可用 |
| `turns/min`（LLM 段） | 完成的 LLM 调用数 ÷ 墙钟 | 合成负载下的吞吐代理，与 `step/min` 同向 |
| `p50 / p95 每轮时延` | 单轮 LLM 调用墙钟 | 解释吞吐变化的来源 |

### 1.2 辅助（诊断，不作判据）

`recompute_tokens`（Δqueries−Δhits）、`hit_rate`、`moves`、`keep_refresh`、`paused_peak`。

### 1.3 为什么要这样改

我们过去所有结论都建在"重算 token 少了"上，但重算少不等于吞吐高：若省下的重算被搬运的墙钟吃掉，`turns/min` 不动（M12b 就是：重算 −72%，墙钟只 −19%）。
**因此 v2 的每条判据都以吞吐表述，并把"重算"写在括号里当解释。**

代价关系（必须显式写出）：

```
重算省下 → 每轮时延下降 → turns/min 上升        （这才是我们想要的链路）
搬运墙钟 → 直接进关键路径 → 可能抵消             （必须扣掉）
```

**推论**：搬运必须发生在 program **不占关键路径**的时刻（等工具期间），否则吞吐收益会被搬运成本吃掉——这条把 E4（时机）从"有意思"升级为"决定成败"。

## 3. 决策模型：三种动作、一条不等式

对每个 program 的驻留上下文，在压力出现时三选一：

| 动作 | 代价 | 收益 | 谁付钱 |
|---|---|---|---|
| `Evict` | 下次回来付 `c_rec(p)`，且以后每次回来都付 | 不占卡 | 该 program，反复付 |
| `Migrate` | `c_mig(p)`（capture+pull+握手） | 保住块 | 自己付一次；目标卡占 `p` |
| `Keep` | 每次 ≈38 token 计算 | 保住块 | 自己反复付，且抢别人算力 |

实测（1466 token 前缀）：`c_rec ≈ 0.23 s`、`c_mig ≈ 0.11~0.12 s` ⇒ **搬运只值一次重算的一半左右**，所以单次"搬一次省一次"几乎不赚；收益来自**避免反复驱逐**。

### 3.1 收益不等式

```
吞吐收益 ≈ [ N·q·c_rec(p) − c_mig(p) − λ·p ] / 单轮总时延
              ↑省下的重算      ↑搬运成本     ↑占用目标卡的机会成本
```

- **该搬** ⇔ `N·q·c_rec(p) > c_mig(p) + λ·p`
- 代入 `c_mig ≈ 0.5·c_rec` ⇒ **`N·q > 0.5 + λ·p/c_rec`**，即 `N·q ≥ 2` 才稳赚
- **该驱逐** ⇔ `N ≤ 1`（一次性）或 `q ≈ 0`（本来活得了）或 `p` 很小（重算便宜）

### 3.2 四个决策轴

| 轴 | 变量 | 要的答案形态 |
|---|---|---|
| D1 会不会回来 | 剩余轮数 `N` | 用历史轮数 + 工具等待时长估计 |
| D2 回来时还活着的概率 | `q = f(压力, gap)` | 一张曲面 + 拟合函数 |
| D3 目的地是否真空闲 | `λ = f(目标占空比)` | "够空"的判据 |
| D4 时机 | 压力瞬间 / 工具等待 / 回来前 | 决定吞吐能否兑现 |

| 事实 | 来源 | 可信度 |

| 能力 | 现状 | 约束 |

## 6. 环境与资源计划

### 6.1 拓扑假设

```
[客户端/agent] → [Residency Controller] → [executor × N] → [vLLM × N]
                       (1 容器)              (1 卡 1 容器)     (1 卡 1 容器)
```

- 每个 SSH = 一张卡的 Docker，卡内 vLLM 监听 `127.0.0.1:8000`（或容器内网 IP + 端口）；
- 控制器与 executor 可以同容器，也可以分离；**一卡一容器**是硬约束，所以"聚合双卡"要用两条 SSH 组网。

### 6.2 每个实验的卡数声明（写在实验说明里）

| 实验 | 卡数 | 是否要求同机 | 理由 |
|---|---|---|---|
| E-env 连通性 | 2 | 先同机，再抽查跨机 | 决定"主动搬迁"是否有物理基础 |
| E0 基线 | 2 | 是 | 需要一个可搬运的对端 |
| E1 `q` 曲面 | **1** | — | 单卡即可测驱逐 |
| E2 临界点 | 2 | 是 | 搬 vs 不搬 |
| E3 目的地质量 | **3** | 是 | 需要"第三张卡"区分"空"与"更空" |
| E4 时机 | 2 | 是 | 只改时机 |
| E5 与 TA 联动 | 2 | 是 | TA 需要多后端 |
| E6 真实 agent | 2 | 是 | 吞吐指标 |
| E7 消融 | 2~3 | 是 | 特征剔除 |
| E8 失败模式 | 2~3 | 是 | 制造目的地也满 |
| E9 Mod 验收 | 2~3 | 是 | 端到端证明 |

**申请三卡只在 E3 / E7 / E8 / E9 需要**，其余两卡即可；E1 单卡（最容易抢）。

## 7. 实验序列

### E-env — 跨容器 p2p 连通性（半天，**新增且必须先做**）

- **问题**：两条 SSH 的两张卡，能否构成 KV 搬运链路？延迟多少？
- **装置**：两容器各起一台 vLLM（两侧 `kv_role=kv_both`），用官方 proxy 形态发一次请求。
- **变量**：容器网络模式（host / bridge）、是否同机。
- **判据**：`c_mig(1466 tok) ≤ 0.3 s` 且首 token 正常 ⇒ 通过；`> 0.6 s` 或不通报废这条路。
- **预期**：同机 bridge 能通但可能慢于同进程（多一跳网络栈）。
- **产物**：`data/e_env_p2p.csv` + 结论"主动搬迁在本环境可行/不可行"。

### E0 — 基线（半天，2 卡）

- 三臂：裸 TA / 我们只钉不搬 / 我们钉+搬；负载 1:1（日常形态）。
- **判据（吞吐版）**：三臂 `turns/min` 差 ≤ 3% 才算打平；任一臂差 > 5% 必须先解释。
- 预期打平。意义：确认"日常不加分也不减分"。

### E1 — 驱逐损害曲面 `q(pressure, gap)`（1 天，1 卡）

- **问题**：走开之后回来还在的概率，随竞争强度与离开时长怎么变？
- **装置**：单卡；10 resident（3k 词）× 压力档 0/0.5/1.0/1.6/3.3× 容量 × gap 1/5/15/60 s（20 格）。
- **判据**：拟合出 `q` 单调下降曲线，给出 `q<0.1` 的临界压力；**吞吐影响**：记录每格 `turns/min`。
- **预期**：`pressure<0.6` 时 `q≈1`（搬了白搬）；`>1.2` 时 `q≈0`。
- **反例**：若 `q` 在 0.6~1.2 平缓过渡 ⇒ 存在"部分驱逐"，但**我们没有搬部分块的能力**，须在文档明写局限。

### E2 — 搬 vs 驱逐的临界点（1 天，2 卡）

- 源卡 pressure 0.35/0.7/1.2/1.6 四档 × 两臂（Evict / Migrate），源卡与目标卡都可作发送方。
- **判据（吞吐版）**：1.2 档搬臂 `turns/min` 比不搬高 ≥15%；0.8 档不低 >3%。
- 预期：0.8 持平、1.2 明显好、1.6 双崩（目的地也满）。

### E3 — 目的地选择质量（1 天，**3 卡**）

- 第三卡预置 0 / 0.5× / 1.0× 负载，看"搬到多空的卡"收益差。
- **判据**：目标卡 1.0× 负载时搬过去是否反而更差 ⇒ 证明 `λ` 必须进判据。
- 产物：`λ(占空比)` 曲线 + 目标卡筛选规则。

### E4 — 时机（1 天，2 卡）

- 三个触发时机：压力瞬间 / **工具等待开始时** / 回来前 2 s。
- **判据**：以 `turns/min` 为主，搬运墙钟计入分母。
- 预期：工具等待期最好——这是把"搬"移出关键路径的唯一办法。
- **意义**：直接回答"program 调完工具回来发现 KV 全没了"的正确处置方式。

### E5 — 与 TA 联动（1 天，2 卡）

- `ta` / `ta+ours` 两臂，同负载、同硬倾斜。
- **判据（吞吐版）**：`ta+ours` 的 `turns/min` ≥ `ta` 的 1.1 倍才算叠加有效。
- 预期：TA 的暂停降低 `q`，该搬窗口更窄——可能是旧结果"TA 在环时搬家无用"的真因。

### E6 — 真实 agent 流量（2 天，2 卡）

- mini-swe-agent（`job_id` = program_id），20~30 实例，记录轮数/gap/命中/`step/min`。
- **判据**：用真实数据拟合的 `q` 与 E1 差 ≤ 0.15；否则重标阈值。
- 预期：真实 gap 长但并发低 ⇒ `q` 偏高 ⇒ **日常不需要搬**（这是合法且重要的结论）。

### E7 — 策略消融（1 天，2~3 卡）

- 全策略 / 去 `q` / 去 `λ` × 两档负载。判据：压力档不劣于全策略 5%，日常档不劣于基线 3%。

### E8 — 失败模式（半天，2~3 卡）

- 目的地也满、连续搬同一 program、搬运中目标卡来了新 program。每个都要有检测 + 回退 guard。

### E9 — Mod 验收（1 天，2~3 卡）

见 §8。

## 8. Mod 交付：Residency Controller Mod

### 8.1 形态（对照 `request-throttling-controller`）

| 项 | 我们的做法 |
|---|---|
| 入口 | 独立进程，OpenAI 兼容 `/v1/chat/completions`，读 `program_id`（body / extra_body / `x-program-id`） |
| 内部 | program 表 → 驻留决策（Evict/Migrate/Keep）→ 转发到 N 个 executor |
| 开关 | `--enable` / `--kill-switch`：关掉后**纯透传**，用于 A/B 与线上回滚 |
| 观测 | `/healthz`、`/metrics`（集群口径）、`/v1/programs` 快照 |
| 部署 | 一个 Docker，配置 `endpoints=card0@http://...,card1@http://...` |
| 依赖 | 只依赖 stdlib + `httpx`；不修改 vLLM/TA |

### 8.2 验收（这就是"证明其效果"）

| 场景 | 对照 | 判据 |
|---|---|---|
| 压力档（热卡 1.2× 容量） | 裸 TA（LRU 被动驱逐） | `step/min`（或 `turns/min`）+≥20% |
| 日常档（两卡 1:1） | 裸 TA | 不低于 3% |
| 真实 agent（E6 负载） | 裸 TA | `step/min` 不低于 0；报告 `q`<0.5 时不搬的比例 |

**验收报告必须三列都给：通关/不达标/解释。** 达不到第一行就写"当前平台不成立"。

### 8.3 与 TA 的关系

- 若 TA 在环：Mod 位于 TA 之后（TA 决定"能否跑"，Mod 决定"块留哪"）；
- 若不在环：Mod 直接接 vLLM，仍可用（这样"证明效果"的实验不被 TA 的暂停干扰）。
- **两套账的风险**：Mod 搬完必须把 pin 同步给 TA（`sync_pin`），否则 TA 会把 program 又派回原卡 → 循环搬家。E5 专测这条。

## 10. 红线

1. **压力档必须比裸 TA 的 `turns/min` 高 ≥20%**（E2）；达不到 = 方向不成立，如实写。
2. **日常档不得低 >3%**（E0）。
3. 收益必须能归因到"决策"而非"载体"（同载体两臂）。
4. 所有数字同机、同引擎版本、同负载、同口径；**跨环境数字不得并表**。
5. 出现"我们更差"必须指到具体决策错了哪一步。

## 11. 风险与回退

| 风险 | 触发 | 回退 |
|---|---|---|
| 跨容器 p2p 不通/太慢 | E-env | 放弃主动搬迁，改做"卡内 keep + 准入"，并如实报告 |
| 搬运成本被低估 | E2 的 0.8 档更差 | 补 `c_mig(p)` 曲线，上调阈值 |
| `q` 无法估计 | E1 曲面不单调 | 退化为"压力阈值触发"，承认无预测能力 |
| 与 TA 双账打架 | E5 循环搬家 | Mod 单方面决定，TA 只读 |
| 真实流量不需要搬 | E6 `q≈1` | 结论改成"仅批处理/大促场景需要"，合法 |
| 两卡不够 | E2 的 1.6 档双崩 | 申请三卡或明说需要 ≥3 卡 |

## 13. 附录

### 13.1 度量定义

- `turns/min` = 完成 LLM 调用数 ÷ 墙钟（分），**必须注明是否含首轮**
- `step/min` = agent 完成步数 ÷ 墙钟（仅真实 agent）
- `recompute_tokens = Δqueries − Δhits`（每次实验前重启引擎）
- `hit_rate = Δhits / Δqueries`，含首轮时上限 `(T−1)/T`
- `q` = 回来那一轮的单 program `hit_rate`
- `pressure_ratio` = 该卡 pin 住的 program 前缀和 ÷ 该卡容量
- `c_mig(p)` / `c_rec(p)` = 目标卡首 token 墙钟（分别带/不带 `kv_transfer_params`）

### 13.2 参数表

| 参数 | 值 |
|---|---|
| 单卡容量 | 与 `--max-model-len`、`--gpu-memory-utilization` 强相关：121,088（16k/0.85）或 47,616（4k/0.6） |
| `c_rec`(1466 tok) | 0.23 s |
| `c_mig`(1466 tok) | 0.11~0.12 s（同机）；跨容器待测 |
| keep 单次 | ≈38 token |
| 搬家饱和点 | `⌈(D−K)/p⌉` |

**用吞吐说话：压力档要把 `turns/min` 抬起来，日常档要证明没拖慢。** 搬运只是手段，且它只在"program 去等工具的那一刻"搬才可能不亏——其余时刻搬，都是拿吞吐换重算。

## 编号勘误（2026-10-28）

前两轮我把两个**单价测量**误标成了路线图里的 E2 / E3。真实对应关系：

| 我实际做的 | 曾误标为 | 正确编号 | 卡数 | 说明 |
|---|---|---|---|---|
| q 曲面（粗扫 + 加密 + 升/降序） | E1 / E1e | **E1** | 1 | 与路线图一致 |
| ping 单价（0.126 s vs 0.599 s） | E2 | **E1b** | 1 | 是"单价"，不是"临界点" |
| 重算成本随前缀线性（118 µs/token） | E3 | **E1c** | 1 | 是"单价模型"，不是"目的地质量" |
| 搬 vs 不搬的临界点 A/B | 未做 | **E2** | **2** | 路线图原义，尚欠 |
| 目的地质量（空 vs 更空） | 未做 | **E3** | **3** | 路线图原义，尚欠 |

因此：**E3 确实需要三张卡**；我这轮跑的所谓 E3 是 E1c（单卡），不占三卡名额。

## 附：判据修订（2026-10-29）

### 为什么废掉 turns/min 作主判据

同一臂内，8 个真实 SWE 实例的墙钟在 **61 s ~ 341 s** 之间摆动（3.6 倍），而同一批跑次的：

- 总 token：218k ~ 230k（恒定）
- 前缀命中率：77.0% ~ 78.6%（恒定）
- `paused_count`：全程 **0**（TA 没有暂停任何 program）

采样显示引擎"至少 1 个请求在跑"的时间占比 **97%**，但并发均值只有 **1.36**（峰值 4）——请求被工具端（docker exec / 测试执行）阻塞，不是被引擎或 TA 卡住。

因此 `turns/min` 量到的主要是"容器冷启动与工具命令时长"，用它比策略会把环境抖动当成策略优劣。

### 新判据（v3）

| 层级 | 指标 | 口径 | 用途 |
|---|---|---|---|
| 主 | **TTFT p50 / p95** | `vllm:time_to_first_token_seconds_bucket` 差分 | 模型侧，跨臂可直接比 |
| 主 | **模型侧 token 速率** | (Δprompt + Δgeneration) ÷ 模型活跃时间 | 需采样 `num_requests_running > 0` |
| 辅 | 前缀命中率、重算量 | 计数器差分 | 解释变量 |
| 辅 | 墙钟、turns/min | 端到端 | 仅在两臂同一模式下并列 |

### 方法学坑（新增第 10 条）

**跨两层 ssh 的命令里不要再嵌引号。** 采样器里用 `awk '... printf \"%.0f %.0f %.0f\" ...'` 经 `ssh "..."` 传下去后，转义引号被吃空，采样列全为空（`active=0` 就是这么来的）。改用 `awk '{print r, p, g}'`（无引号、无 printf）后正常。
