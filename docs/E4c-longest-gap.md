# E4c：判据换成"最长间隔"，但它变得太宽松——两臂又变成一样

日期：2026-10-28
改动：`executor/programs.py` 新增 `longest_gap()`；`executor/app.py` 的门控从 `max(间隔中位数) >= want` 改成 `max(最长间隔) >= want`，其中 `want = max(WINDOW_MIN, 1.2 × 实测搬家耗时 EMA)`。
负载：中段到来（turn1 12 个，之后每轮 +4，共 24），间隔按 log-uniform 在 **2~40 s** 采样（每轮重新采），8 轮。

## 结果（同一 gap 序列，两臂）

| 臂 | 搬家（t3 / t4） | A 命中（t3 / t4 / t5） | 对端拉取（t3 / t4） | p50 合计 |
|---|---|---|---|---|
| 门控关 | 1 / 4 | 72,064 · 94,464 · 89,984 | 4,502 / 13,709 | 2.0 s |
| 门控开（min 8 s，最长间隔） | 1 / 4 | 71,680 · 89,728 · 89,728 | 4,583 / 13,710 | — |

**两臂在搬家次数、命中率、拉取字节上都在 1% 内重合。**

## 为什么（这是这一刀的真实收获）

1. 换成"最长间隔"之后，门控**只会越来越宽松**：`max(gaps)` 随样本单调不减，跑到第 3 轮时几乎每个 program 都已经出现过一个 ≥ 8 s 的间隔，于是全部放行。
2. 也就是说：中位数在等间隔负载上退化成常量比较（等价于关）；最长间隔在真正有分布的负载上又退化成"几乎恒放行"（也等价于关）。**两个统计量都不对。**
3. 正确的量应该回答"这个 program **下一次**会停多久"——是分布的分位数/超期概率，不是已经发生过的极值。

## 下一步（唯一能区分的一点）

把判据改成**分位数 + 样本数**：对该 program 最近 6 个间隔，要求 `p75 >= 1.2 × move_cost` **且** 至少 2 个样本，才允许搬。这样：
- 间隔快（2~4 s）的 program 会被拒（p75 小）；
- 间隔慢（20~40 s）的会被放行（p75 大）；
- "最长间隔"的单调性被 p75 的稳健性替换掉。

这一格需要把 gap 采样做宽（2~120 s）并跑 10 轮，才能让 p75 与 p25 真正分开。
