# 两个待补格的结论（推导 + 已有数据，非新跑）

日期：2026-10-28。两格都因引擎状态问题没能新跑，但都能用已有测量把答案定下来。

## 1) E5：真搬 vs pin —— 迁移被 pin 支配（严格劣）

已有三个数（都是实测）：

| 量 | 值 | 来源 |
|---|---|---|
| pin 相对 free 省下的首轮中位时延 | **0.276 s**（1.142 → 0.866） | 冷启动错配格，N=12 |
| 9k token 前缀的本地 prefill | ≈ **0.67 s**（73 µs/token，由 4247 tok → 0.31 s 线性外推） | E1c |
| 跨卡搬运 / 本地重算 | **0.61×** | E-env（100% external hits） |

⇒ 一次真搬的代价 ≈ 0.61 × 0.67 = **0.41 s**，而它最多只能拿回 **0.276 s**。

**结论**：在这个场景里，迁移能拿到的收益上限就是 pin 的收益（都消除了同一段重算），但 pin 是零成本、迁移要付 0.41 s。所以**迁移严格劣于“把路由指对”**。

适用范围要说清楚：只有当 **不能改路由**（放置权在 TA 手里、且 TA 不让你钉）或 **KV 必须跟随工作而不是反过来**（负载中途变化、program 被 TA 迁卡）时，迁移才有存在意义 —— 那时它买到的是"避免重算 0.67 s"，代价 0.41 s，净赚 0.26 s/次。

## 2) E4：定额公式要不要带负载项

已有两个数：

| 量 | 值 | 来源 |
|---|---|---|
| 中等负载下单次搬迁实际耗时 | **≈0.6 s** | E2/E4 各轮日志 |
| 少搬一个的代价（定额 4 vs 8，4000 词） | p50 0.90 vs 0.20 → **0.70 s/轮 × 剩余 6 轮 = 4.2 s** | E4e |

⇒ 判据不是"move_cost 固定"，而是：

```
worth_moving  ⇔  move_cost  <  turns_remaining × (p50_miss − p50_hit)
```

即 **`ceil((D−K)/p̄)` 这个数量公式不需要负载修正，但需要一条可行性检查**：
当队列很长、move_cost 升到 ≈1.8 s 时，只要还剩 ≥3 轮就仍然划算（1.8 < 3×0.70）。
只有当"剩 1~2 轮"且"高负载"同时成立时，才应该少搬 —— 那是**尾部决策**，不是定额本身要改。

所以 E4 的答案是：定额数量不变，末尾加一条 `if move_cost > turns_remaining × penalty: skip`。
