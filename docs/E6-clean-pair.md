# E6-clean：单卡冷启动成对对比（n=2）

日期：2026-10-29
装置：同一张卡、同一引擎配置（`--max-model-len 12288 --gpu-util 0.80 --enable-prefix-caching`，892 块 ×128 = 114,176 token）；
**每次跑前按 PID 杀引擎 + `fuser -k /dev/davinci*` + 重启并断言 `etime < 240 s`**；
客户端 mini-swe-agent 1.14.4，切片 0:18，`--workers 8`，`--redo-existing`；
两臂均 `backends` 断言通过（裸 TA = `[8110]`，我们 = `[8101]`）。

| 臂 | 跑次 | 墙钟 | Δqueries | Δhits | 命中率 |
|---|---|---|---|---|---|
| 裸 TA 直连 | 1 | 241 s | 516,317 | 390,272 | 75.59% |
| 裸 TA 直连 | 2 | 253 s | 516,870 | 399,744 | 77.34% |
| 我们（executor 在前） | 1 | 246 s | 489,182 | 380,160 | 77.71% |
| 我们（executor 在前） | 2 | 329 s | 508,564 | 392,448 | 77.17% |

均值：裸 TA **76.5%**、我们 **77.4%**（+0.97 pt）。
同一臂内跑间极差：裸 TA 1.75 pt、我们 0.54 pt。

## 读法

1. **跑间波动（1.75 pt）大于两臂均值差（0.97 pt）** ⇒ 这一档**没有可测差异**，不能说我们更好，也不能说更差。
2. 我们两跑的 query 数略少（489k/508k vs 516k/517k），说明经过 executor 后重发/重试略少，但命中比例没变。
3. 墙钟上我们有 1 个 329 s 的离群（另一次 246 s），裸 TA 241/253 s 更稳——这一层多一跳带来的尾部风险是真实存在的。
4. 结论与之前所有格一致：**TA 已经做了准入与落点时，我们这层在命中率与吞吐上都落不进差异区**；它的价值只在"能把 KV 主动搬走"这个原语（E2 离径版 10.72 s → 1.32 s、kv_both 双向可用）。

## 复现要点（踩过的坑）

- `pkill -f` 在本环境**不可靠**（返回被吞、旧引擎被当成新引擎）→ 必须按 `ps` 拿 PID `kill -9`，并断言 `health` 先变 000；
- 杀完必须 `fuser -k -9 /dev/davinciN`，否则残留显存让新引擎 `Engine core initialization failed`；
- 客户端在 tm4 上走 `ssh -L 9000` 隧道，容器重启后隧道必须重建，否则**一次请求都发不出去而你以为它在跑**（本次就踩到，Δq=0 才发现）；
- `/v1/completions` 在 TA 上返回 404，探针要用 `/v1/chat/completions`；模型名是 `Qwen2.5-14B-Instruct`（不是路径）。
