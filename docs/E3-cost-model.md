# E3 — 两个单价：ping 是平的，重算是线性的

日期：2026-10-27　容器 B（NPU 3，单卡 114,176 token）
装置修正两次后才有意义：①5000 词会超 `max-model-len 8192` 报 400，改用 4000 词上限；
②按 0.5× 容量灌 filler 不足以驱逐（5 个 resident 时总数才 0.68×），改成"灌到哨兵 resident 不再命中"（实际灌了 240k）。

## 数据（`data/e3_cost_model.csv`）

| 前缀 | prompt token | ping（缓存命中时） | 重算（被驱逐后） | 倍数 | 每 token 重算成本 |
|---|---|---|---|---|---|
| 1000 词 | 1,685 | 0.116 s | 0.204 s | 1.75× | 120.8 µs |
| 2500 词 | 4,247 | 0.129 s | 0.505 s | 3.92× | 118.9 µs |
| 4000 词 | 6,809 | 0.133 s | 0.794 s | 5.98× | 116.5 µs |

**两个单价**：
- **ping ≈ 0.12 s，与前缀长度几乎无关**（1.7k → 6.8k 只涨 0.017 s）——开销是固定请求成本，不是前缀计算。
- **重算 ≈ 118 µs/token，严格线性**（三档的 µs/token 相差不到 4%）。

## 由此得到的换算

`1 次 ping ≈ 0.12 s ≈ 1000 token 的重算`。所以：

| 动作 | 成本（以 4247-token 的 program 为例） |
|---|---|
| ping 一次 | 0.13 s |
| ping 三次（10 s 间隔 / 30 s 空窗） | 0.39 s |
| ping 六次（10 s 间隔 / 60 s 空窗） | 0.77 s |
| **搬一次（0.61× 重算，E-env 测得的系数）** | **0.31 s** |

**交叉点：约 2.4 次 ping**。也就是说——

- 空窗 **≤ 25 s**（10 s 间隔 → 2~3 次 ping）：**保活更便宜**；
- 空窗 **> 25 s**：**搬更便宜**（0.31 s 一次付清，且搬完是"在另一张卡上活着"，不是"靠续命吊着"）；
- 前缀越大，这个结论越偏向"搬"：因为 ping 成本不随前缀涨，但重算（以及按比例算的搬迁成本）涨，交叉点从 1.4 次 ping（1.7k）移到 3.4 次（6.8k）——但**绝对差**同时放大。

## 对策略的直接含义

```
idle 预计 < 25 s   → ping（10 s 一次，别更密）
idle 预计 > 25 s   → 交给搬迁（0.61× 一次性），或直接放弃
流动量 > 0.45×容量 → ping 无意义（块已没），只剩搬或放弃
```

这三条把 E1（何时丢）、E2（丢/保单价比）、E3（两种保法的交叉点）串成了一条完整的判据链。

## 诚实边界

- "被驱逐后"这一档的 q 是 **0.20 而不是 0**（240k filler 只敲掉约 80%），所以重算成本是"80% 前缀"的实测值，真实全量重算会再高约 20%；倍数（1.75/3.9/6.0）因此是**下界**。
- 搬迁系数 0.61 来自 E-env（812 token、跨容器），与本实验的 118 µs/token 不是同一套引擎参数，混算时只应看**量级**；严格起见下一步应在同一引擎上重测 0.61。
- ping 成本是在引擎空闲时测的；有竞争时 ping 自身会排队变慢（未测）。
